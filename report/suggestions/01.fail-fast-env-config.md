# 01. Replace the fallback-value env helper with fail-fast validated config

- **Rank: 9 / 10** (impact if adopted)
- **Side: Server** (with a small parallel change on the client)
- **Effort: Small.** One new file, one deleted file, ~20 import updates

## Current picture

`server/src/utils/dotenvHelper.ts` reads every variable with an `||` fallback:

```ts
const env: EnvVariableType = {
  NODE_ENV: process.env.NODE_ENV || "development",
  PORT: process.env.PORT || "3001",
  MONGODB_COMPASS_CONNECTION_STRING: process.env.MONGODB_COMPASS_CONNECTION_STRING || "mongodb://connection-string-not-found",
  CORS_ORIGIN: process.env.CORS_ORIGIN || "*",
  ACCESS_TOKEN_SECRET: process.env.ACCESS_TOKEN_SECRET || "fallback-access-token-secret",
  REFRESH_TOKEN_SECRET: process.env.REFRESH_TOKEN_SECRET || "fallback-refresh-token-secret",
  CLOUDINARY_API_KEY: process.env.CLOUDINARY_API_KEY || "0",
  GMAIL_PASSWORD: String(process.env.GMAIL_PASSWORD),
  ...
};
```

The design intent is clear. The app should always start. The consequence is that a misconfigured deployment starts *successfully* in a broken or insecure state, and you find out later from user reports rather than from the process refusing to boot.

Three concrete failure modes this produces:

- **Silent auth compromise.** Missing token secrets → publicly known fallback → forgeable tokens (`vulnerabilities/01.hardcoded-fallback-jwt-secrets.md`).
- **Silent outage.** Missing `CORS_ORIGIN` → allowlist of `["*"]` → matches no real origin → every browser request fails CORS while the server reports healthy (`vulnerabilities/18.cors-allows-requests-with-no-origin.md`).
- **Nonsense values reaching external services.** `String(undefined)` is the literal string `"undefined"`, sent to Gmail as a password. `CLOUDINARY_API_KEY || "0"` sends `"0"` as an API key.

There is also a subtler issue: `dotenv.config()` on line 5 resolves `.env` relative to `process.cwd()`. Running the compiled output from the repository root instead of from `server/` silently loads nothing.

## Proposed picture

A config module that validates at import time and throws with an actionable message. Nothing downstream changes except the import path.

```ts
// server/src/config/env.ts
import dotenv from "dotenv";
import path from "path";

dotenv.config({ path: path.resolve(__dirname, "../../.env") });

const missing: string[] = [];

const required = (key: string, minLength = 1): string => {
  const value = process.env[key]?.trim();
  if (!value || value.length < minLength) {
    missing.push(minLength > 1 ? `${key} (min ${minLength} chars)` : key);
    return "";
  }
  return value;
};

const optional = <T>(key: string, fallback: T, parse: (v: string) => T): T => {
  const value = process.env[key]?.trim();
  return value === undefined || value === "" ? fallback : parse(value);
};

const config = {
  NODE_ENV: optional("NODE_ENV", "development" as const, String),
  PORT: optional("PORT", 3001, Number),
  LOG_LEVEL: optional("LOG_LEVEL", "info", String),

  MONGODB_URI: required("MONGODB_COMPASS_CONNECTION_STRING"),
  DB_NAME: required("DB_NAME"),

  ACCESS_TOKEN_SECRET: required("ACCESS_TOKEN_SECRET", 32),
  REFRESH_TOKEN_SECRET: required("REFRESH_TOKEN_SECRET", 32),
  ACCESS_TOKEN_EXPIRY: optional("ACCESS_TOKEN_EXPIRY", "15m", String),
  REFRESH_TOKEN_EXPIRY: optional("REFRESH_TOKEN_EXPIRY", "7d", String),

  CORS_ORIGIN: required("CORS_ORIGIN"),

  CLOUDINARY_CLOUD_NAME: required("CLOUDINARY_CLOUD_NAME"),
  CLOUDINARY_API_KEY: required("CLOUDINARY_API_KEY"),
  CLOUDINARY_API_SECRET: required("CLOUDINARY_API_SECRET"),

  EMAIL_PROVIDER_API_KEY: required("EMAIL_PROVIDER_API_KEY"),
  EMAIL_PROVIDER_API_URL: optional("EMAIL_PROVIDER_API_URL", "https://api.resend.com/emails", String),
  EMAIL_FROM_ADDRESS: required("EMAIL_FROM_ADDRESS"),
  RECIPIENT_MAIL_ID: required("RECIPIENT_MAIL_ID"),
};

if (missing.length > 0) {
  throw new Error(
    `FATAL: missing or invalid environment variables:\n` +
    missing.map((k) => `  - ${k}`).join("\n") +
    `\n\nSet them in server/.env (development) or in your host's environment ` +
    `settings (production). See server/.env.example.\n`
  );
}

// invariants that a per-variable check cannot express
if (config.ACCESS_TOKEN_SECRET === config.REFRESH_TOKEN_SECRET) {
  throw new Error("FATAL: ACCESS_TOKEN_SECRET and REFRESH_TOKEN_SECRET must differ.");
}
if (config.CORS_ORIGIN.split(",").some((o) => o.trim() === "*")) {
  throw new Error("FATAL: CORS_ORIGIN must not contain '*' — credentials require explicit origins.");
}
if (!Number.isInteger(config.PORT) || config.PORT < 1 || config.PORT > 65535) {
  throw new Error(`FATAL: PORT must be an integer 1-65535, got "${process.env.PORT}".`);
}

export const env = config;
export default env;
```

Two design points worth calling out:

**Collect all failures, then throw once.** Throwing on the first missing variable means a five-variable misconfiguration takes five deploy cycles to resolve. The `missing[]` array reports everything at once.

**Distinguish `required` from `optional` explicitly.** The current file makes every variable look optional because they all have `||`. Reading the new file tells you at a glance which are credentials and which are tunables. Nothing that grants access has a default.

### Import it first

```ts
// server/src/index.ts
import "./config/env";          // must be line 1 — fail before binding a port
import env from "./config/env";
import mongodbConnect from "./db/mongodb.connect";
import { app } from "./app";
```

Currently `app.ts` throws its CORS error at module scope during import, which produces an unhandled exception with a stack trace rather than a readable message. Moving validation to a dedicated module that runs first makes the failure legible.

### Add `.env.example`

```bash
# server/.env.example — commit this; never commit .env
NODE_ENV=development
PORT=3001
LOG_LEVEL=debug

MONGODB_COMPASS_CONNECTION_STRING=mongodb://127.0.0.1:27017
DB_NAME=playtube

# generate with: openssl rand -hex 64
ACCESS_TOKEN_SECRET=
REFRESH_TOKEN_SECRET=
ACCESS_TOKEN_EXPIRY=15m
REFRESH_TOKEN_EXPIRY=7d

# comma-separated, no wildcards
CORS_ORIGIN=http://localhost:5173

CLOUDINARY_CLOUD_NAME=
CLOUDINARY_API_KEY=
CLOUDINARY_API_SECRET=

EMAIL_PROVIDER_API_KEY=
EMAIL_PROVIDER_API_URL=https://api.resend.com/emails
EMAIL_FROM_ADDRESS=
RECIPIENT_MAIL_ID=
```

This is the file that makes onboarding possible. Right now a new clone has no way to know what to configure, which is precisely why fallbacks got added in the first place. `.env.example` solves that problem properly.

## The client side

`client/src/utilities/envHelper.ts` has the mirror-image problem:

```ts
export const env = {
  VITE_SERVER_URL: import.meta.env.VITE_SERVER_URL as string,
} as const;
```

The `as string` cast is unchecked. If `VITE_SERVER_URL` is unset, every request goes to `undefined/users/login`, which the browser resolves relative to the current origin, producing 404s from your static host rather than an obvious configuration error.

Vite inlines `import.meta.env` at build time, so this fails at **build** time if you check it, which is exactly when you want to know:

```ts
// client/src/utilities/envHelper.ts
const serverUrl = import.meta.env.VITE_SERVER_URL;

if (!serverUrl || typeof serverUrl !== "string") {
  throw new Error(
    "VITE_SERVER_URL is not set. Add it to client/.env before building."
  );
}
if (!/^https?:\/\//.test(serverUrl)) {
  throw new Error(`VITE_SERVER_URL must be an absolute URL, got "${serverUrl}".`);
}

export const env = {
  VITE_SERVER_URL: serverUrl.replace(/\/$/, ""),   // normalise trailing slash
} as const;
```

The trailing-slash normalisation is worth having: every call site writes `` `${URL}/users/login` ``, so a configured value ending in `/` produces a double slash. Currently that is handled by nobody.

**Reminder about `VITE_` variables:** anything prefixed `VITE_` is inlined into the JavaScript bundle and is public. Never put a secret there. Your `client/.env` currently holds only `VITE_SERVER_URL`, which is correct.

## Migration

```bash
cd server
# 1. add the new file, then rewrite imports
grep -rln "utils/dotenvHelper" src/ | xargs sed -i 's#utils/dotenvHelper#config/env#g'
# note: adjust the relative depth per file, or use a tsconfig path alias

# 2. rename MONGODB_COMPASS_CONNECTION_STRING → MONGODB_URI at the two use sites
# 3. delete the old file
rm src/utils/dotenvHelper.ts

# 4. verify
npx tsc --noEmit
```

Then **rotate `ACCESS_TOKEN_SECRET` and `REFRESH_TOKEN_SECRET`**, see `vulnerabilities/01.hardcoded-fallback-jwt-secrets.md` for why. This logs everyone out once, which is the intended effect.

## Interaction with other documents

- Closes `vulnerabilities/01.hardcoded-fallback-jwt-secrets.md` entirely. That document describes the problem; this is the design.
- Supplies the boot-time `"*"` rejection that `vulnerabilities/18.cors-allows-requests-with-no-origin.md` also implements at the CORS layer. Duplicating the check is intentional and harmless.
- `vulnerabilities/15.smtp-tls-verification-disabled-and-debug-logging.md` recommends deleting `mail.service.ts`. If you do, remove the five `GMAIL_*` variables from the config above. They are omitted from my example already, since `mailHttp.service.ts` is the live path.
- `03.security-middleware-baseline.md` assumes `env` is available and validated when `app.ts` runs. Apply this first.
- Zod is proposed in `02.central-validation-layer.md` for request validation. You *could* use it here too (`z.object({...}).parse(process.env)`). I have deliberately not, to keep the config module dependency-free so it can be the first import in the process. Either is fine; do not do both.
