This is not an abstract quality complaint. Several findings in this audit are things a first-week test suite would have caught immediately, and would have caught *at the moment they were introduced* rather than months later:

| Finding | The test that catches it |

Eight real defects, all catchable by assertions that take one line each.

## Proposed picture

### Stack

```bash
cd server
npm i -D vitest supertest @types/supertest mongodb-memory-server
```

- **Vitest** over Jest: native ESM/TypeScript, no `ts-jest` transform config, much faster startup.
- **Supertest** drives the Express app in-process — no port binding, no running server.
- **mongodb-memory-server** spins up a real MongoDB per test run. Not a mock: aggregation pipelines, `$facet`, unique-index violations, and text indexes all behave exactly as in production. Given how much of this codebase's logic lives in aggregation pipelines, mocking Mongoose would test almost nothing.

```ts
// server/vitest.config.ts
import { defineConfig } from "vitest/config";

export default defineConfig({
  test: {
    environment: "node",
    globals: true,
    setupFiles: ["./tests/setup.ts"],
    testTimeout: 30_000,       // memory-server download on first run
    fileParallelism: false,    // one shared in-memory DB
  },
});
```

```ts
// server/tests/setup.ts
import { MongoMemoryReplSet } from "mongodb-memory-server";
import mongoose from "mongoose";
import { beforeAll, afterAll, afterEach } from "vitest";

let replSet: MongoMemoryReplSet;

beforeAll(async () => {
  // ReplSet, not MongoMemoryServer — transactions require it (see suggestions/12)
  replSet = await MongoMemoryReplSet.create({ replSet: { count: 1 } });
  await mongoose.connect(replSet.getUri(), { dbName: "test" });
});

afterEach(async () => {
  const collections = await mongoose.connection.db!.collections();
  await Promise.all(collections.map((c) => c.deleteMany({})));
});

afterAll(async () => {
  await mongoose.disconnect();
  await replSet.stop();
});
```

`MongoMemoryReplSet` rather than `MongoMemoryServer` is a deliberate choice — it matches the replica-set requirement of the transactional cascade deletes in `12.atomic-cascade-deletes.md`, so those are testable.

### Fixtures

```ts
// server/tests/helpers/factories.ts
import request from "supertest";
import { app } from "../../src/app";
import { User } from "../../src/models/user.model";

let seq = 0;

export const makeUser = async (overrides: Partial<UserInput> = {}) => {
  const n = ++seq;
  const password = overrides.password ?? "correct-horse-battery";
  const user = await User.create({
    username: `user${n}`,
    email: `user${n}@example.test`,
    fullname: `User ${n}`,
    password,
    ...overrides,
  });
  return { user, password };
};

/** Log in and return the cookie jar for authenticated requests. */
export const loginAs = async (username: string, password: string): Promise<string[]> => {
  const res = await request(app)
    .post("/api/v1/users/login")
    .send({ username, password })
    .expect(200);
  return res.headers["set-cookie"] as unknown as string[];
};
```

### The first tests to write

Authorization boundaries, because that is where the confirmed bugs are.

```ts
// server/tests/auth.test.ts
describe("authentication", () => {
  it("rejects an unauthenticated request to a protected route", async () => {
    await request(app).get("/api/v1/users/current-user").expect(401);
  });

  it("does not return tokens in the login response body", async () => {
    const { user, password } = await makeUser();
    const res = await request(app)
      .post("/api/v1/users/login")
      .send({ username: user.username, password })
      .expect(200);

    expect(res.body.data).not.toHaveProperty("accessToken");
    expect(res.body.data).not.toHaveProperty("refreshToken");
    expect(res.headers["set-cookie"].join()).toContain("HttpOnly");
  });

  it("returns the same error for a wrong username and a wrong password", async () => {
    const { user } = await makeUser();
    const a = await request(app).post("/api/v1/users/login")
      .send({ username: "nobody", password: "wrong" });
    const b = await request(app).post("/api/v1/users/login")
      .send({ username: user.username, password: "wrong" });

    expect(a.status).toBe(b.status);
    expect(a.body.message).toBe(b.body.message);
  });

  it("revokes existing sessions when the password changes", async () => {
    const { user, password } = await makeUser();
    const cookies = await loginAs(user.username, password);

    await request(app).post("/api/v1/users/change-password").set("Cookie", cookies)
      .send({ currentPassword: password, newPassword: "a-different-long-password" })
      .expect(200);

    await request(app).post("/api/v1/users/refresh-token").set("Cookie", cookies).expect(401);
  });
});
```

```ts
// server/tests/authorization.test.ts
describe("object-level authorization", () => {
  it("does not let a stranger delete a playlist", async () => {
    const owner = await makeUser();
    const stranger = await makeUser();
    const ownerCookies = await loginAs(owner.user.username, owner.password);
    const strangerCookies = await loginAs(stranger.user.username, stranger.password);

    const { body } = await request(app).post("/api/v1/playlists")
      .set("Cookie", ownerCookies).send({ name: "Mine" }).expect(200);
    const id = body.data.playlist._id;

    await request(app).delete(`/api/v1/playlists/${id}`)
      .set("Cookie", strangerCookies)
      .expect(404);                                   // currently returns 200

    expect(await Playlist.findById(id)).not.toBeNull();
  });

  it("hides unpublished videos from strangers but shows them to the owner", async () => {
    const owner = await makeUser();
    const cookies = await loginAs(owner.user.username, owner.password);
    const video = await Video.create({ owner: owner.user._id, isPublished: false, /* ... */ });

    await request(app).get(`/api/v1/videos/${video._id}`).expect(404);
    await request(app).get(`/api/v1/videos/${video._id}`).set("Cookie", cookies).expect(200);
  });

  it("does not let anyone write to another user's watch history", async () => {
    const victim = await makeUser();
    const video = await Video.create({ owner: victim.user._id, /* ... */ });

    await request(app)
      .post(`/api/v1/users/history/${video._id}?userId=${victim.user._id}`)
      .expect(401);                                   // currently returns 200

    const after = await User.findById(victim.user._id);
    expect(after!.watchHistory).toHaveLength(0);
  });

  it("actually deletes the account", async () => {
    const { user, password } = await makeUser();
    const cookies = await loginAs(user.username, password);

    await request(app).delete("/api/v1/users/delete-user").set("Cookie", cookies).expect(200);

    const after = await User.findById(user._id);
    expect(after === null || after.isDeleted).toBe(true);   // currently: neither
  });
});
```

```ts
// server/tests/exposure.test.ts
describe("data exposure", () => {
  const FORBIDDEN = ["email", "password", "refreshToken", "watchHistory", "isAdmin"];

  it("does not leak private fields in search results", async () => {
    await makeUser({ username: "searchme" });
    const { body } = await request(app).get("/api/v1/search/q/searchme").expect(200);
    for (const field of FORBIDDEN) {
      expect(body.data.user[0]).not.toHaveProperty(field);
    }
  });

  it("caps search results", async () => {
    for (let i = 0; i < 150; i++) await makeUser({ username: `bulk${i}` });
    const { body } = await request(app).get("/api/v1/search/q/bulk").expect(200);
    expect(body.data.user.length).toBeLessThanOrEqual(20);
  });

  it("clamps an oversized pagination limit", async () => {
    const { body } = await request(app).get("/api/v1/feeds?limit=1000000").expect(200);
    expect(body.data.pagination.limit).toBeLessThanOrEqual(100);
  });
});
```

Note these are written against the **fixed** behaviour. Run them now and they fail — that is the point. They are executable specifications for the rest of this report, and they are the fastest way to verify you have actually closed each finding.

### CI

```yaml
# .github/workflows/ci.yml
name: CI
on: [push, pull_request]
jobs:
  server:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: "22", cache: npm, cache-dependency-path: server/package-lock.json }
      - run: npm ci
        working-directory: server
      - run: npx tsc --noEmit
        working-directory: server
      - run: npm test
        working-directory: server
```

The `tsc --noEmit` step is worth having on its own — the server has `strict: true` but no CI check, so a type error only surfaces when someone runs `npm run build`.

Add ESLint to the server package too. It has none (only `client/eslint.config.js` exists), and `no-constant-condition` alone would have flagged the `if (0)` in `deleteUser`.

## Realistic scope

Do not attempt broad coverage. Twenty tests covering authentication, object-level authorization, and data exposure catch most of what matters and take an afternoon. Coverage percentage is not the goal — the goal is that the eight bugs in the table above cannot come back.
