# 22. The health check requires authentication, so nothing can monitor it

- **Rank: 5 / 10**
- **Side: Server**
- **Effort: Tiny**

## Current picture

```ts
// server/src/routes/healthCheck.route.ts
const healthCheckRouter = Router();
healthCheckRouter.use(verifyJWT);          // applied to every route in this file

healthCheckRouter.route("/").get(healthCheck);
healthCheckRouter.route("/user").get(checkUserAuthDetails);
```

`GET /api/v1/health` returns **401** to any caller without a valid access token.

An uptime monitor, a load balancer, a container orchestrator, or Render's own health probe cannot use it. `logs/http.log` shows exactly this happening:

```json
{"level":"http","message":"Request completed","method":"GET","statusCode":401,"url":"/api/v1/health"}
```

Two endpoints with different audiences got the same middleware because `router.use()` applies to the whole file:

- `GET /health` — "is the service up?" Infrastructure. Must be anonymous.
- `GET /health/user` — "who am I?" A session lookup that happens to live in this file. Must be authenticated.

There is a second problem: the check does not check anything.

```ts
// server/src/controllers/healthCheck.controller.ts
const healthCheck = asyncHandler(async (req, res) => {
  const response = new ApiResponse(200, {}, "SERVICE IS HEALTHY");
  return res.status(200).json(response);
});
```

It returns 200 as long as Express is running. If MongoDB is unreachable — every request 500s, the app is completely non-functional — this still reports healthy. A health check that cannot report unhealthy provides no signal.

## Proposed picture

### Split by audience

```ts
// server/src/routes/healthCheck.route.ts
import { Router } from "express";
import { liveness, readiness } from "../controllers/healthCheck.controller";
import { checkUserAuthDetails } from "../controllers/userControllers/getCurrentUser";
import { requireAuth } from "../middleware/auth.middleware";

const healthCheckRouter = Router();

healthCheckRouter.route("/").get(liveness);        // public
healthCheckRouter.route("/ready").get(readiness);  // public
healthCheckRouter.route("/user").get(requireAuth, checkUserAuthDetails);

export default healthCheckRouter;
```

`GET /health/user` is a duplicate of `GET /users/current-user` — both return `req.user`. Consider removing it, or making it an alias, once `04.unify-auth-session-model.md` establishes `GET /users/me` as the single session endpoint.

### Liveness vs readiness

The distinction matters for orchestrators, and it is worth having even without one:

- **Liveness** — "is the process alive?" If this fails, restart me. It must not depend on external services: a Mongo outage should not cause a restart loop, because restarting does not fix Mongo.
- **Readiness** — "can I serve traffic?" If this fails, stop routing to me but do not restart. Dependencies belong here.

```ts
// server/src/controllers/healthCheck.controller.ts
import mongoose from "mongoose";

export const liveness = asyncHandler(async (_req, res) => {
  return res.status(200).json({ status: "ok", uptime: Math.floor(process.uptime()) });
});

export const readiness = asyncHandler(async (_req, res) => {
  const checks: Record<string, "ok" | "fail"> = {};

  // readyState 1 === connected
  checks.database = mongoose.connection.readyState === 1 ? "ok" : "fail";

  if (checks.database === "ok") {
    try {
      // a ping proves the connection is usable, not merely open
      await mongoose.connection.db!.admin().ping();
    } catch {
      checks.database = "fail";
    }
  }

  const healthy = Object.values(checks).every((v) => v === "ok");

  return res.status(healthy ? 200 : 503).json({
    status: healthy ? "ok" : "degraded",
    checks,
    uptime: Math.floor(process.uptime()),
  });
});
```

Three deliberate choices:

**The response is not wrapped in `ApiResponse`.** Health endpoints are consumed by infrastructure, not by your client. A flat, stable shape that never changes is more useful than a project envelope. This is the one documented exception to `16.consistent-response-envelope.md`.

**503 on failure, not 200.** Monitors key on status code. Reporting `{"status": "degraded"}` with HTTP 200 means nothing alerts.

**Nothing sensitive is exposed.** No version string, no dependency versions, no connection details, no hostnames — these endpoints are public. Do not add `mongoose.version` or the connection host "for debugging"; that is free reconnaissance.

### Exempt it from rate limiting

`03.security-middleware-baseline.md` adds a global limiter. A monitor polling every 30 seconds is well within 300/minute, but if you tighten the limit later, an alert storm caused by your own rate limiter is a confusing outage to diagnose.

```ts
// server/src/middleware/rateLimit.middleware.ts
export const globalLimiter = rateLimit({
  windowMs: 60_000,
  limit: 300,
  skip: (req) => req.path.startsWith("/api/v1/health"),
  handler,
});
```

### Exempt it from request logging

A monitor polling every 30 seconds writes 2,880 log lines per day of pure noise:

```ts
// server/src/middleware/requestLogger.middleware.ts
if (req.path.startsWith("/api/v1/health")) return next();
```

Keep logging health *failures* — the readiness handler can log directly when a check fails.

### Configure your host

On Render, set the health check path to `/api/v1/health` in the service settings. Render polls it and will not route traffic to an instance that fails, and will not mark a deploy successful until it passes. That only works if the endpoint is anonymous — which is the point of this document.

## A note on `notFoundHandler`

Related, in the same area:

```ts
// server/src/middleware/error.middleware.ts:272-274
const error = new ApiError(404, `ROUTE NOT FOUND - ${req.method} ${req.originalUrl}`);
```

This echoes the full requested URL back to the caller. It is not a serious leak — the caller supplied the URL — but it does reflect arbitrary attacker-controlled text into a response body, and every 404 from a vulnerability scanner gets logged at `warn` level with the probe path. Consider a static message and logging the path rather than returning it:

```ts
logService.warn("route not found", { method: req.method, path: req.path });
next(new ApiError(404, "ROUTE NOT FOUND"));
```
