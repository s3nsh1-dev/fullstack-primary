# 03. Establish a security middleware baseline in app.ts

- **Rank: 9 / 10**
- **Side: Server**
- **Effort: Small** — one file, three new dependencies

## Current picture

`server/src/app.ts` registers six middlewares:

```ts
app.use(cors({ ... }));
app.use(express.urlencoded({ extended: true, limit: "16kb" }));
app.use(express.json({ limit: "16kb" }));
app.use(express.static("public"));
app.use(cookieParser());
app.use(requestLogger);
```

What is present is reasonable. The 16 kb body limits are a good default that many projects forget. What is missing:

| Missing | Consequence | Vulnerability doc |
| --- | --- | --- |
| `helmet` | No security headers at all — no HSTS, no `X-Content-Type-Options`, and `X-Powered-By: Express` advertises the stack | — |
| `express-rate-limit` | Unlimited login attempts, contact-form email bombing, registration flooding | `05` |
| `app.set("trust proxy")` | `req.ip` is the proxy's address, so rate limiting and view dedup key on the wrong value | `05` |
| CSRF middleware | `SameSite=None` cookies with no token → forged writes | `03` |
| `compression` | Every JSON response sent uncompressed | — |
| Upload cleanup | Failed requests orphan files on disk | `04` |

And one item that should be **removed**: `express.static("public")` serves the multer staging directory publicly (`vulnerabilities/04`).

## Proposed picture

Order matters here more than in most refactors. Each middleware must run before the ones that depend on it, and cheap rejections must happen before expensive work.

```ts
// server/src/app.ts
import express from "express";
import cors from "cors";
import helmet from "helmet";
import compression from "compression";
import cookieParser from "cookie-parser";

import env from "./config/env";
import { corsOptions } from "./config/cors";
import { globalLimiter } from "./middleware/rateLimit.middleware";
import { verifyCsrf } from "./middleware/csrf.middleware";
import { cleanupUploads } from "./middleware/cleanupUploads.middleware";
import { requestLogger } from "./middleware/requestLogger.middleware";
import { errorHandler, notFoundHandler } from "./middleware/error.middleware";

const app = express();

// 1. Proxy awareness — must be first. Everything downstream that reads
//    req.ip, req.protocol or req.secure depends on it.
app.set("trust proxy", 1);

// 2. Remove the framework fingerprint.
app.disable("x-powered-by");

// 3. Security headers.
app.use(
  helmet({
    // This is a JSON API: it never serves HTML, so a restrictive CSP costs
    // nothing and blocks anything unexpected from executing.
    contentSecurityPolicy: {
      directives: { defaultSrc: ["'none'"], frameAncestors: ["'none'"] },
    },
    // Cross-Origin-Resource-Policy defaults to same-origin, which would block
    // the frontend from reading responses. The CORS config is the control here.
    crossOriginResourcePolicy: { policy: "cross-origin" },
    hsts: env.NODE_ENV === "production"
      ? { maxAge: 31_536_000, includeSubDomains: true, preload: true }
      : false,
  })
);

// 4. CORS — before the rate limiter so preflights are answered cheaply,
//    and before CSRF so OPTIONS is never rejected for a missing token.
app.use(cors(corsOptions));

// 5. Global rate limit — before body parsing, so a flood is rejected
//    before payloads are read into memory.
app.use(globalLimiter);

// 6. Compression.
app.use(compression());

// 7. Body parsing.
app.use(express.json({ limit: "16kb" }));
app.use(express.urlencoded({ extended: true, limit: "16kb" }));
app.use(cookieParser());

// 8. CSRF — after cookieParser (it reads a cookie), before any route.
app.use(verifyCsrf);

// 9. Guaranteed cleanup of multer-staged files, on success and on error.
app.use(cleanupUploads);

// 10. Request logging — after parsing so route info is available,
//     and deliberately without request bodies.
app.use(requestLogger);

// -- routes ------------------------------------------------------------
app.use("/api/v1/users", userRouter);
// ... unchanged ...

app.use(notFoundHandler);
app.use(errorHandler);

export { app };
```

**`express.static("public")` is gone.** Nothing in this application serves static files — the client is a separate Vite build on its own origin. Removing it closes the public-serving half of `vulnerabilities/04`.

```bash
cd server && npm install helmet compression express-rate-limit
npm install -D @types/compression
```

## Notes on the non-obvious choices

**`trust proxy: 1`, not `true`.** `true` trusts the entire `X-Forwarded-For` chain, which the client controls. An attacker prepends a fake IP per request and defeats rate limiting entirely. `1` means "trust exactly one proxy hop" — correct for Render, Railway, Fly, and a single nginx. Behind Cloudflare *and* a platform proxy, use `2`.

**CSP on a JSON API.** `default-src 'none'` looks aggressive but is exactly right for an API that only returns JSON. If anything ever causes HTML to be served from this origin — an error page, a reintroduced static handler — the CSP prevents it from executing script. This is the layer that would have contained the stored-XSS path in `vulnerabilities/04`.

**`crossOriginResourcePolicy: "cross-origin"`.** Helmet's default (`same-origin`) sets a CORP header that blocks your own frontend from reading responses. This is the single most common way a helmet upgrade breaks a separated frontend, and the symptom (a CORS-looking error that CORS config does not fix) is confusing. Set it explicitly.

**Rate limiter before body parsing.** A 16 kb body is small, but reading it still costs an allocation per request. Rejecting at the limiter first is strictly cheaper under a flood.

**CORS before CSRF.** A preflight `OPTIONS` request carries no CSRF token. `verifyCsrf` skips safe methods including `OPTIONS`, so this is belt-and-braces — but the ordering makes the intent explicit and prevents a future change to the safe-methods list from breaking every preflight.

## What about `express-mongo-sanitize`?

Deliberately omitted. Two reasons:

1. **It does not work on Express 5 as-is.** It mutates `req.query`, which in Express 5 is a getter with no setter — it throws. There are forks that write to a separate property; check maintenance status before adopting one.
2. **It is the wrong layer.** It strips `$`-prefixed keys globally, which blunts operator injection but does nothing for the regex, sort-field, or type-confusion cases in `vulnerabilities/12`. Schema validation (`02.central-validation-layer.md`) fixes all of them and gives you types.

If you want it as a backstop after the validation layer is in place, fine. Do not adopt it *instead* of validation.

## Worth adding while you are here

**Request timeouts.** No route has one. A slow Cloudinary call or a hung Mongo query holds a connection indefinitely.

```ts
import timeout from "connect-timeout";
app.use(timeout("30s"));
app.use((req, _res, next) => (req.timedout ? next() : next()));
```

Upload routes need a longer limit — apply per-route rather than globally if you keep server-side uploads. (Moot if you adopt `10.direct-to-cloudinary-uploads.md`.)

**Graceful shutdown improvements.** `server/src/index.ts:27-51` handles `SIGTERM`/`SIGINT` and closes the HTTP server and Mongo connection — genuinely good, and more than most projects do. Two gaps: `server.close()` waits indefinitely for in-flight requests, and neither `uncaughtException` nor `unhandledRejection` is handled.

```ts
const gracefulShutdown = async (signal: string) => {
  logService.info(`${signal} received, shutting down`);
  const forceExit = setTimeout(() => {
    logService.error("Shutdown timed out, forcing exit");
    process.exit(1);
  }, 15_000);
  forceExit.unref();
  // ... existing close logic ...
};

process.on("unhandledRejection", (reason) => {
  logService.error("Unhandled rejection", reason);
  gracefulShutdown("unhandledRejection");
});
process.on("uncaughtException", (error) => {
  logService.error("Uncaught exception", error);
  process.exit(1);        // state is unknown — do not attempt graceful shutdown
});
```

Also replace `let server: any` (line 8) with `let server: import("http").Server | undefined`.
