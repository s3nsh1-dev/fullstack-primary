# 06. Consolidate 40+ hand-written requests into one HTTP client

- **Rank: 8 / 10**
- **Side: Client**
- **Effort: Medium** — one new file, ~60 hook files touched, mechanical

## Current picture

The client makes HTTP requests two different ways, in roughly sixty separate hook files, each re-implementing the same concerns.

**Two libraries.** ~20 files use `axios`; ~40 use `fetch`. Sometimes for the same resource — `useLogin` uses `fetch`, `useChangeUserPassword` uses `axios`.

**The base URL is redeclared everywhere.** `const URL = env.VITE_SERVER_URL;` appears in nearly every hook file, sometimes at the top, sometimes at the bottom.

**Credentials are opt-in per call.** Every request must remember `credentials: "include"` (fetch) or `withCredentials: true` (axios). One omission is a silent auth failure.

**Error handling is bespoke.** Compare:

```ts
// useLogin.ts — a 20-line status-code switch
switch (response.status) {
  case 404: errorMessage = "USER DOES NOT EXIST"; break;
  case 401: errorMessage = "USER PASSWORD IS INCORRECT"; break;
  ...
}

// useUserRegister.ts — one generic message, discards the server's
if (!response.ok) throw new Error("USER REGISTRATION FAILED");

// useChangeUserPassword.ts — stringifies the axios error into the message
catch (error) { throw new Error(`PASSWORD CHANGING REQUEST FAILED: ${error}`); }

// useLogout.ts
if (!response.ok) throw new Error("USER LOG OUT FAILED");
```

The third one is worth a closer look: template-stringifying an axios error produces `"AxiosError: Request failed with status code 400"` — the server's actual message is discarded, and the result is rendered to the user.

**There is no 401 handling.** Access tokens expire after 15 minutes. Nothing detects a 401 and refreshes. The only refresh happens in `useRefreshUser` at app mount. So a user who leaves a tab open for 20 minutes gets failures on every action until they reload.

**Envelope unwrapping is inconsistent.** Some hooks return `data.data`, some `data`, some a nested field. The server always wraps in `{statusCode, data, message, success}`, but no hook agrees on where to stop.

The cost: adding a CSRF header (`vulnerabilities/03`) means editing sixty files. Missing three of them means three broken features.

## Proposed picture

```ts
// client/src/lib/apiClient.ts
import axios, { AxiosError, type AxiosInstance } from "axios";
import { env } from "../utilities/envHelper";

export type ApiEnvelope<T> = {
  statusCode: number;
  data: T;
  message: string;
  success: boolean;
};

export class ApiError extends Error {
  constructor(
    message: string,
    readonly status: number,
    readonly details?: unknown
  ) {
    super(message);
    this.name = "ApiError";
  }
}

const readCookie = (name: string): string | undefined =>
  document.cookie
    .split("; ")
    .find((c) => c.startsWith(`${name}=`))
    ?.split("=")[1];

export const apiClient: AxiosInstance = axios.create({
  baseURL: env.VITE_SERVER_URL,
  withCredentials: true,             // once, for every request
  headers: { "Content-Type": "application/json" },
  timeout: 30_000,
});

// --- request: attach the CSRF token to mutating calls -------------------
apiClient.interceptors.request.use((config) => {
  const method = (config.method ?? "get").toUpperCase();
  if (!["GET", "HEAD", "OPTIONS"].includes(method)) {
    const token = readCookie("csrfToken");
    if (token) config.headers.set("x-csrf-token", token);
  }
  return config;
});

// --- response: refresh once on 401, then retry -------------------------
let refreshPromise: Promise<void> | null = null;

const refreshSession = (): Promise<void> => {
  // Collapse concurrent 401s into a single refresh call. Without this,
  // five parallel requests trigger five rotations and four of them lose.
  refreshPromise ??= apiClient
    .post("/users/refresh-token")
    .then(() => undefined)
    .finally(() => { refreshPromise = null; });
  return refreshPromise;
};

apiClient.interceptors.response.use(
  (response) => response,
  async (error: AxiosError<ApiEnvelope<unknown>>) => {
    const config = error.config as (typeof error.config & { _retried?: boolean }) | undefined;
    const status = error.response?.status;

    const isRefreshCall = config?.url?.includes("/users/refresh-token");
    if (status === 401 && config && !config._retried && !isRefreshCall) {
      config._retried = true;
      try {
        await refreshSession();
        return apiClient.request(config);
      } catch {
        window.dispatchEvent(new CustomEvent("auth:expired"));
        // fall through to the rejection below
      }
    }

    throw new ApiError(
      error.response?.data?.message ?? error.message ?? "REQUEST FAILED",
      status ?? 0,
      (error.response?.data as { errors?: unknown } | undefined)?.errors
    );
  }
);

/** Unwrap the server envelope. Every hook uses this instead of reaching into `.data.data`. */
export const unwrap = async <T>(promise: Promise<{ data: ApiEnvelope<T> }>): Promise<T> =>
  (await promise).data.data;
```

Four details worth calling out:

**Deduplicated refresh.** The `refreshPromise` singleton is the important part. A page load fires several queries at once; if the access token has expired they all 401 simultaneously. Without deduplication each triggers its own `/refresh-token`, and because refresh tokens rotate, the first call invalidates the token the others are using — so four of the five fail and the user is logged out. This is the same class of race described in `14.fix-refresh-token-rotation-race.md`.

**`_retried` guard.** Prevents an infinite loop if the retried request also 401s.

**`isRefreshCall` guard.** A 401 *from* `/refresh-token` means the session is genuinely gone — retrying it recurses.

**`auth:expired` event.** Decouples the client from the auth context. `AuthContextProvider` listens and clears the cache; the HTTP layer does not need to import React.

### Hooks become three lines

```ts
// before — useChangeUserPassword.ts, 40 lines
const changePassword = async (updatedCredentials: CredentialsType) => {
  try {
    const { data } = await axios.post<ApiResponse>(
      `${URL}/users/change-password`,
      updatedCredentials,
      { withCredentials: true }
    );
    return data;
  } catch (error) {
    throw new Error(`PASSWORD CHANGING REQUEST FAILED: ${error}`);
  }
};

// after
const useChangeUserPassword = () =>
  useMutation({
    mutationKey: userKeys.changePassword,
    mutationFn: (credentials: CredentialsType) =>
      unwrap<boolean>(apiClient.post("/users/change-password", credentials)),
  });
```

The server's actual error message now reaches the UI, because `ApiError.message` comes from `error.response.data.message`.

For `FormData` uploads, drop the JSON content type so the browser sets the multipart boundary:

```ts
mutationFn: (formData: FormData) =>
  unwrap<{ video: Video }>(
    apiClient.post("/videos", formData, { headers: { "Content-Type": undefined } })
  ),
```

### Query key factory

While consolidating, replace the ad-hoc key strings. `AuthContextProvider` currently invalidates `["feed", 30]` — a literal that must match whatever `useFetchFeed` used, with nothing enforcing it.

```ts
// client/src/lib/queryKeys.ts
export const authKeys = { session: ["session"] as const };

export const feedKeys = {
  all: ["feed"] as const,
  page: (limit: number) => [...feedKeys.all, limit] as const,
};

export const videoKeys = {
  all: ["videos"] as const,
  detail: (id: string) => [...videoKeys.all, id] as const,
  byUser: (userId: string, page: number) => [...videoKeys.all, "user", userId, page] as const,
};
```

`invalidateQueries({ queryKey: feedKeys.all })` now invalidates every feed page regardless of limit, which is what the current code is trying to do and does not.

## Migration

Incremental and safe — `apiClient` and the old hooks coexist.

1. Add `apiClient.ts` and `queryKeys.ts`.
2. Convert the auth hooks first: `useLogin`, `useLogout`, `useRefreshUser`/`useSession`, `useUserRegister`. These are where the 401 interceptor matters most.
3. Convert the remaining axios hooks (~20) — nearly find-and-replace.
4. Convert the fetch hooks (~40).
5. Delete `const URL = env.VITE_SERVER_URL;` from every hook file.

```bash
cd client
grep -rln "env.VITE_SERVER_URL" src/hooks/ | wc -l    # progress metric
```
