# 05. No rate limiting on any endpoint

- **Rank: 8 / 10**
- **Side: Server**
- **Category:** Brute force / resource exhaustion / cost abuse
- **Location:** `server/src/app.ts` (absence), `server/package.json` (no rate-limit dependency)

## The issue

There is no rate limiting anywhere in the application. `server/package.json` has no `express-rate-limit`, no `rate-limiter-flexible`, no equivalent. `app.ts` registers `cors`, `express.urlencoded`, `express.json`, `express.static`, `cookieParser`, and `requestLogger`, and then goes straight to the routers.

Every endpoint accepts unlimited requests from a single source.

## What this exposes

### Credential brute force: `POST /api/v1/users/login`

`loginUser` (`server/src/controllers/userControllers/loginUser.ts`) does a Mongo lookup and one `bcrypt.compare` per attempt. bcrypt at cost 10 is roughly 50-100 ms, which is a real per-attempt cost but nowhere near a defence when an attacker can run 200 concurrent connections. There is no attempt counter, no account lockout, no exponential backoff, no CAPTCHA.

Combine with `14.weak-registration-validation.md`, where registration enforces no minimum password length or complexity, so accounts protected by `1234` exist by construction. That makes this the single most likely way the application actually gets broken into.

The endpoint also returns distinguishable errors: `404 "USER DOES NOT EXIST"` vs `401 "USER PASSWORD IS INCORRECT"`. That is a username oracle, and it means an attacker can enumerate valid usernames first and then spray passwords only against confirmed accounts. Combined with `09.email-addresses-exposed-on-public-endpoints.md` (which hands out email addresses) the attacker gets a target list for free.

### Email/cost abuse: `POST /api/v1/contact`

```ts
contactRouter.post("/", contactFormValidation, submitContactForm);   // contact.route.ts:29
```

No auth, no rate limit, no CAPTCHA. Each call causes an outbound HTTP request to Resend (`mailHttp.service.ts:38`) which sends a real email to `RECIPIENT_MAIL_ID`, your inbox.

An attacker scripts this and your mailbox receives thousands of messages. Worse, it burns your Resend quota, and because `reply_to` is attacker-controlled, your verified sending domain is used to relay attacker-chosen reply addresses. Sustained abuse gets a sending domain flagged, at which point your legitimate transactional mail stops being delivered, a reputational cost that takes weeks to undo.

### Registration flooding: `POST /api/v1/users/register`

Unlimited account creation, each one uploading files to Cloudinary (see `04.unauthenticated-file-upload-to-public-directory.md`). Cloudinary storage and transformation quota is billed. This is a direct route from "anonymous attacker" to "your card is charged".

### View-count inflation: `POST /api/v1/views/:videoId`

`view.controller.ts:41` builds its dedup fingerprint as:

```ts
const fingerprint = userId?.toString() || `${ipAddress}-${userAgent}`;
```

For anonymous callers, both halves are attacker-controlled. `User-Agent` is a request header, and `req.ip` is derived from the proxy chain with no `trust proxy` configured. Vary the `User-Agent` string per request and every request looks like a distinct viewer, defeating the 24-hour duplicate check on line 46. Unlimited requests then means unlimited fake views, plus one `View` document written to Mongo per request.

### Expensive query abuse: search and feed

`GET /api/v1/search/q/:searchText` runs four collection queries in parallel with an unanchored `$regex` and **no result limit at all** (`searchUserText.controller.ts`). `GET /api/v1/feeds` sorts the entire `videos` and `tweets` collections on an unindexed field. Neither is cheap, and neither is bounded. See `13.unbounded-pagination-and-unpaginated-search.md`.

## The fix

Install `express-rate-limit`. Use *tiered* limits. A single global limit is either too loose for login or too tight for browsing.

```bash
cd server && npm install express-rate-limit
```

```ts
// server/src/middleware/rateLimit.middleware.ts
import rateLimit, { ipKeyGenerator } from "express-rate-limit";
import ApiError from "../utils/ApiError";

const handler = () => {
  throw new ApiError(429, "TOO MANY REQUESTS, PLEASE TRY AGAIN LATER");
};

/** Baseline for all traffic. Generous — this only stops crude floods. */
export const globalLimiter = rateLimit({
  windowMs: 60_000,
  limit: 300,
  standardHeaders: "draft-7",
  legacyHeaders: false,
  handler,
});

/** Credential endpoints. Keyed on IP + submitted identifier so one attacker
 *  cannot lock out a whole NAT, and one account cannot be sprayed from one IP. */
export const authLimiter = rateLimit({
  windowMs: 15 * 60_000,
  limit: 10,
  skipSuccessfulRequests: true,      // only failures count toward the limit
  keyGenerator: (req) =>
    `${ipKeyGenerator(req.ip ?? "")}:${String(req.body?.username ?? req.body?.email ?? "")}`,
  handler,
});

/** Account creation. */
export const registerLimiter = rateLimit({
  windowMs: 60 * 60_000,
  limit: 5,
  handler,
});

/** Anything that costs money per call: outbound email, media upload. */
export const expensiveLimiter = rateLimit({
  windowMs: 60 * 60_000,
  limit: 10,
  handler,
});

/** Unbounded-work reads: search, feed. */
export const searchLimiter = rateLimit({
  windowMs: 60_000,
  limit: 30,
  handler,
});
```

Applied:

```ts
// server/src/app.ts
app.use(globalLimiter);

// server/src/routes/user.routes.ts
userRouter.route("/login").post(authLimiter, loginUser);
userRouter.route("/register").post(registerLimiter, imageUpload.fields([...]), registerUser);
userRouter.route("/change-password").post(authLimiter, requireAuth, changeCurrentPassword);

// server/src/routes/contact.route.ts
contactRouter.post("/", expensiveLimiter, contactFormValidation, submitContactForm);

// server/src/routes/video.route.ts
videoRouter.route("/").post(expensiveLimiter, requireAuth, videoUpload.fields([...]), publishAVideo);

// server/src/routes/searchUserText.route.ts / feed.route.ts
searchUserTextRouter.route("/q/:searchText").get(searchLimiter, searchingText);
feedRouter.get("/", searchLimiter, getFeed);
```

Note `registerLimiter` is placed **before** the multer middleware. Order matters: if multer runs first, the upload is already written to disk before the limiter rejects the request, which defeats the purpose for the disk-exhaustion case in document 04.

### Prerequisite: configure `trust proxy`

This is required, not optional. You are deployed behind a proxy (Render/Railway/Cloudflare). Without it, `req.ip` is the *proxy's* address for every request, so every visitor shares one rate-limit bucket. The first ten failed logins from anyone lock out the entire internet.

```ts
// server/src/app.ts, before any middleware
app.set("trust proxy", 1);   // 1 = trust exactly one proxy hop
```

Do not use `app.set("trust proxy", true)`. That trusts the full `X-Forwarded-For` chain, which the client controls, letting an attacker forge a fresh IP per request and bypass the limiter entirely. Set it to the actual number of proxies in front of you.

`trust proxy` also fixes the wrong `ipAddress` currently being recorded in `view.model.ts` documents.

### Also close the username oracle

Return one indistinguishable error for both failure modes:

```ts
// server/src/controllers/userControllers/loginUser.ts
const matchedUser = await User.findOne({ ... });
const isPasswordValid = matchedUser
  ? await matchedUser.isPasswordCorrect(password)
  : false;

if (!matchedUser || !isPasswordValid) {
  throw new ApiError(401, "INVALID CREDENTIALS");
}
```

Note the deliberate structure: the bcrypt comparison is skipped when the user does not exist, which makes the no-such-user path measurably faster and reintroduces a timing oracle. If you care about that, run a dummy `bcrypt.compare` against a fixed hash in the else branch to equalise timing. For this application's threat model, the status-code fix alone is the meaningful part.

This change requires a matching client update. `client/src/hooks/data-fetching/useLogin.ts:31-49` maps status codes to user-facing strings and currently distinguishes 404 from 401.

## Interaction with other documents

- **Prerequisite for** `04.unauthenticated-file-upload-to-public-directory.md`. Size limits bound one request; rate limits bound the number of requests. Neither is sufficient alone.
- `13.unbounded-pagination-and-unpaginated-search.md` reduces the *cost per request* for search and feed; this document reduces the *number of requests*. Apply both.
